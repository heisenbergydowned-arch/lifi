# OLED 接收显示

本版按用户指定接线：**OLED SCL → PB8，SDA → PB9；蜂鸣器 IN → PB6**。OLED 电源 3.3V，所有模块共地。PB7 未使用。CubeMX 已保存并生成对应 GPIO 配置，Keil 已加入显示模块和 OLED 包含路径。

沿用加入工程的 `OLED/OLED.c/.h` 与 8×16 ASCII 字库：128×64 屏幕，4 行、每行 16 个字符，SSD1306 式页寻址，I²C 7 位地址 0x3C（写地址字节 0x78）。SCL/SDA 均为开漏、空闲高电平；模块没有上拉时，各补 4.7kΩ 到 3.3V。不同地址可修改 `OLED_I2C_WRITE_ADDRESS`；屏幕型号/字库不同需要按实际驱动适配。当前显示英文和数字，不支持中文字库。

## 显示内容

下两行始终用于正文：解出一个字母就加入正在接收的文字；结束暗光达到 10T 后，显示完整消息并保留到下一次接收。服务器确认并移除网络队列后，屏幕仍保留本地文字。切 T 或 ADC 缺样时丢弃未完成文字，回到上一次完整消息。复位后历史消息不保留。

上两行每 3 秒轮换一组状态。下面只是示意，实际数值来自接收器和模块：

```text
A1 T60ms          TIME 22:13:56    ESP:VPS OK
#1 P1/1           ADC:0530 L:0     ACK1 Q0
HELLO WORLD       HELLO WORLD     HELLO WORLD
```

- `A1`：接收地址编号，来自 `DEVICE_ADDRESS`。
- `T60ms`：当前点长 T，按键切换后状态页自动回到 T 显示。
- `RX...`：正在拼接消息；`#1`：第 1 条完整消息，编号与串口上报一致。
- `P1/3`：正文第 1/3 页；每页最多 32 字符。接收中跟随最新一页；收完从第一页开始，每 4 秒自动翻页，最多显示 96 字符。
- `TIME`：DS1302 当前时分秒，每秒读取一次；未接/未校准/日期无效时显示 `--:--:--`。完整接收日期、时间及开机计数仍在串口/网站记录里。
- `ADC`：最近消费的原始 12 位 ADC 值，未经中值滤波或明暗极性转换；`L` 是滤波和阈值判决后的亮暗状态。显示值是间隔读取的状态，不代表完整波形。
- `ESP`：最近一条通过 CRC 校验的模块状态，例如 `WAIT`、`WIFI OFF`、`WIFI OK`、`UPLOADING`、`VPS OK`、`HTTPS ERR`。它不带心跳，**不是实时在线探测**；模块随后断电时，旧状态可能保留。
- `ACK1 Q0`：本次开机已匹配的服务器确认次数为 1，STM32 尚有 0 条排队消息。只有消息身份和 CRC 匹配的确认才增加 ACK；Wi-Fi 连上不等于消息上传完成。

正常接收 `SOS`/`HELP` 并触发原有 60 秒蜂鸣器时，第一行持续显示 `!ALARM SOS/HELP!`。这代表报警定时器仍在运行；其间收到其他文字会更新正文，报警提示在计时结束后退出。新求救消息仍会重新计时 60 秒。

## 异常提示

|提示|含义|
|---|---|
|CALIBRATING... / Keep torch OFF|上电采集环境光基线，先关闭手机手电筒|
|WAIT DARK SYNC|等待连续暗光完成同步，再发送|
|CAL ERROR / Torch OFF+reset|基线没有足够判决余量，关灯、检查分压和照明后复位|
|ADC ERROR / RESET RECEIVER|ADC/DMA 故障或回调丢失已使接收停止，串口查看具体原因|
|RX HAS ERRORS|消息包含解码错误，正文中的 `?` 不作为有效求救词|
|TEXT TRUNCATED|超过 96 字符，明确标记截断，不作为有效求救词|

## 代码分工与运行顺序

`OLED` 负责现有 GPIO 软件 I²C 和字符绘制；`ReceiverDisplay.c/.h` 负责布局和刷新。`MessageService_GetDisplayState` 提供当前残文或上次完整消息，`LdrReceiver_GetStatus` 提供采样/判决状态，`ESP8266_GetLastStatus` 提供最近模块状态。

`main.c` 的 USER CODE 区域调用 `ReceiverDisplay_Init()`，位置在 `LdrAdc_Start()` 前。驱动上电等待和整屏清零仅在这里执行。主循环先消费 ADC，再处理按键、蜂鸣器、网络，最后调用 `ReceiverDisplay_Process()`；后者每 100 ms整理一次画面，每次最多绘制一个变化的字符，扫描时轮换位置，长文字不会一直被状态栏挤占。

显示刷新不重新初始化 GPIO/ADC/定时器，不关中断，不调用运行期 `HAL_Delay` 或整屏清屏。现有 OLED 驱动发送时没有检测 ACK，所以未接屏幕不会无限等待，但软件也不能据此确认屏幕存在。实际软件 I²C 速率、字形方向和电气时序仍需上板检查。

## 上板核对

1. 将蜂鸣器从原 PB8 改接 PB6，OLED 按 PB8/PB9 接线，烧录 `Firmware/STM32-Morse-IoT.hex`。
2. 上电关灯等待标定和同步提示结束，发送 `HELLO`，检查屏幕、串口和完整消息编号一致。
3. 发较长英文消息验证三页显示；再发 `E`，确认旧文字已擦除。
4. 切换 60/120/240 ms 并同步调整手机 T；发送 SOS，检查报警显示和蜂鸣器 60 秒结束。
5. 对比状态页 ADC 与串口原始值；检查长时间连续接收时无新增 `[LDR] WARNING: dropped samples` 或 ADC/DMA 错误。有示波器时同时观察光敏分压和 OLED SCL，以实测评估刷新耗时。

主机逻辑测试和 Keil 编译不能代替屏幕点亮、真实采样时序、蜂鸣器声音或 RTC 走时验证。
